📋 RESUMEN DEL TRABAJO
───────────────────────────────────────────────────────────────────────────────

El chatbot de Gemini ha sido adaptado para respetar la estructura de roles del
hotel. Ahora cada rol (ADMIN, ALMACENISTA, SERVICIO, RECEPCIÓN) ve solo los
datos que le corresponden y recibe respuestas personalizadas según su función.

ANTES:  ⚠️  Un chatbot universal que podía mostrar cualquier dato a cualquier usuario
DESPUÉS: ✅ Un chatbot que entiende roles y respeta permisos

🏗️ ARQUITECTURA TÉCNICA
───────────────────────────────────────────────────────────────────────────────

FLUJO DE SOLICITUD:
  1. Usuario (+ rol) envía pregunta
  2. AiController extrae autenticación + rol
  3. RoleContextInfo creado con info del usuario
  4. InventoryAssistantService recibe RoleContextInfo
  5. RoleBasedContextFilter filtra datos según rol
  6. RoleBasedPromptBuilder obtiene instrucciones del rol
  7. Prompt construido con: instrucciones + contexto filtrado + pregunta
  8. Gemini API recibe prompt adaptado
  9. Respuesta retornada (sin datos no permitidos)

COMPONENTES:

📊 EJEMPLOS DE RESPUESTAS
───────────────────────────────────────────────────────────────────────────────

PREGUNTA: "¿Cuál es el estado general del inventario?"

ADMIN responde:
  ✓ Analiza completo del sistema
  ✓ Métricas de usuarios, habitaciones, productos
  ✓ Recomendaciones estratégicas

ALMACENISTA responde:
  ✓ Solo datos de bodega
  ✓ Productos a reabastecer (ordenados por urgencia)
  ✓ Movimientos recientes
  ✗ NO ve habitaciones ni usuarios

SERVICIO responde:
  ✓ Consumo por tipo de cuarto
  ✓ Sugerencias de reposición por piso
  ✓ Sus movimientos propios
  ✗ NO ve bodega ni stock general

RECEPCIÓN responde:
  ✓ Estado de habitaciones
  ✓ PAR (Producto Asignado por Rol)
  ✓ Ocupancy
  ✗ NO ve datos de bodega ni análisis detallados
